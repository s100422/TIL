# 미니프로젝트1 - 고객 VOC 자동 분류 & 긴급 알림 워크플로우

## 1. 프로젝트 소개

고객들이 구글 폼으로 문의(VOC)를 남기면, 사람이 일일이 읽고 분류하고 급한 건인지 판단하는 게 번거로워서 이 과정을 자동화하였다.
구글 폼으로 문의가 들어오면 n8n이 자동으로 감지해서, AI가 문의 내용을 분석하고 분류한 다음 결과를 시트에 정리해주고, 긴급한 문의는 디스코드로 바로 알림까지 오게 만드는 걸 목표로 했다.

## 2. 사용한 것

- **Google Form** : 고객이 문의를 남기는 창구
고객 VOC 폼 링크: https://forms.gle/GKAzPGa7E1c74agAA
고객 VOC(응답): https://docs.google.com/spreadsheets/d/1Im0rdHwGFjUx9EBj2daHWEwZtTrSm9N5jRboNoPWSQM/edit?usp=sharing
분석결과시트: https://docs.google.com/spreadsheets/d/1eF892nb_M79jzYIAl-NQ7Jau7emk_-qmJtLKyN9eAGc/edit?usp=sharing
- **Google Sheets** : 폼 응답이 쌓이는 시트(고객 VOC(응답)) + 분석 결과가 쌓이는 시트(분석 결과 시트)
- **n8n** : 전체 자동화 흐름을 짜는 도구
- **Google Gemini** : 문의 내용을 분류하는 AI 모델
- **Discord Webhook** : 긴급한 문의 알림용

## 3. 전체 흐름

```
폼 제출
  → 1. 트리거 (새 응답 감지)
  → 2. 중복 확인 (이메일 + 물품번호로 판단) → 순번 생성
  → 3. AI가 문의 내용 분류 (분류/감정/긴급도/요약)
  → 4. 결과값 검증 (이상한 값 나오면 기본값으로 안전하게 처리)
  → 5. 분석 결과 시트에 저장
  → 6. 긴급도가 '상'이면 디스코드로 알림
```

## 4. 단계별로 뭘 했는지

### 1단계. 트리거

폼 응답이 쌓이는 시트를 감시하는 **Google Sheets Trigger** 노드를 사용. Row Added 이벤트로 새 행이 추가되면 그걸 감지해서 워크플로우가 시작 (1분 간격으로 확인)

### 2단계. 중복 확인

처음엔 시트에 순번 열을 만들어서 그걸로 "이미 처리한 행인지" 판단하려고 했다. 그런데 프로젝트를 진행하면서 생각해보니 진짜 막아야 하는 건 "같은 고객이 같은 물품번호로 또 문의하는 것"이었다. 그래서 판단 기준을 **이메일 + 물품번호 조합**으로 바꿨다.

분석 결과 시트를 조회해서 같은 이메일+물품번호 조합이 이미 있으면 중복으로 보고 처리를 멈추고 고객 이메일로 안내 메시지를 보내도록 하고, 없으면 새로운 문의로 보고 다음 단계로 넘어가게 했다. 이 조회 결과를 그대로 활용해서 **순번(Ref_No)도 이 단계에서 같이 만든다.** 형식은 `VOC-날짜-순번` (예: VOC-20260805-001) 이다.

### 3단계. AI 분류

**AI Agent** 노드에 Google Gemini를 연결해서 문의 내용을 넣으면 아래 4가지를 판단하게 했다.

- category : 결제 / 계정 / 상품 / 배송 / 기타
- sentiment : 긍정 / 중립 / 부정
- urgency : 상 / 중 / 하
- summary : 80자 이내 요약

AI 응답이 정해진 형식(JSON)으로 나오도록 **Structured Output Parser**를 붙였다.

### 4단계. 검증 안전판

AI가 항상 우리가 원하는 형식대로 답을 준다는 보장이 없어서, 그걸 걸러내는 단계를 따로 만들었다. 처음엔 Structured Output Parser의 Auto-Fix Format 기능(AI가 형식 어기면 자동으로 다시 물어보는 기능)을 켜려고 했는데, 그러려면 모델 서브노드를 하나 더 연결해야 해서 굳이 그렇게까지 할 필요는 없다고 판단했다. 대신 Code 노드로 직접 검증하는 방식으로 갔다.

체크하는 것들:
- category / sentiment / urgency가 정해둔 값 목록에 있는지
- summary가 문자열이고 80자 이내인지
- 이메일 형식이 맞는지, 물품번호가 5자리 숫자인지

여기서 하나라도 이상하면 urgency는 안전하게 '중'으로, needs_review 칸에는 '리뷰확인 필요'라고 표시되게 했다. AI가 에러를 내더라도(응답 자체를 못 받은 경우) 워크플로우가 멈추지 않고 이 로직을 그대로 타고 시트에 기록되게 했다.

### 5단계. 시트 저장

Google Sheets Append 노드로 분석 결과 시트에 한 행씩 쌓는다. Code 노드에서 나온 필드 이름이랑 시트 헤더 이름을 똑같이 맞춰놔서 자동 매핑되게 했다.

### 6단계. 디스코드 알림

긴급도가 '상'인 것만 걸러서 디스코드 웹훅으로 알림을 보낸다. 메시지는 항상 같은 형식으로 나가게 고정해뒀다 (Ref_No, 분류, 감정, 요약, 원문 내용 포함).

## 5. 하면서 막혔던 부분들

### 순번 자동 채우기가 계속 오류남
처음엔 시트에서 ARRAYFORMULA로 순번을 자동으로 채우려고 했는데, 아래 행에 뭐라도 값이 하나 들어가 있으면 계속 REF 에러가 났다. 행마다 독립된 수식으로 바꿔서 미리 몇천 행 채워두는 방법도 써봤는데, 이것도 결국 언젠가 또 채워야 하는 문제라 별로였다. 그래서 아예 시트 수식을 없애고 **n8n Code 노드에서 순번을 직접 계산**하는 방식으로 바꿨다. (분석 결과 시트에서 같은 날짜로 시작하는 Ref_No 개수를 세서 다음 번호를 만드는 방식)

### IF 노드에 아무것도 안 들어오는 문제
중복 확인할 때 시트에서 조회했는데 매칭되는 게 없으면 노드가 아이템을 아예 안 내보내서 그 다음 IF 노드까지 데이터가 안 넘어가는 문제가 있었다. **Always Output Data** 옵션을 켜야 매칭이 안 되어도 빈 아이템을 내보내줘서 그 다음 로직이 정상적으로 돌아간다는 걸 알게 됐다.

### AI Agent 결과값이 이상하게 다 기본값으로 나옴
검증 로직을 만들어놨는데 AI가 제대로 답을 줬는데도 계속 다 기본값(기타/중립/중)으로 바뀌는 버그가 있었다. 알고 보니 AI Agent 노드에 Output Parser를 붙이면 결과가 `output`이라는 키 안에 한 번 더 감싸져서 나온다는 걸 몰라서 생긴 문제였다. `$json.category`가 아니라 `$json.output.category`로 접근해야 했다.

### 물품번호 "00001"이 숫자로 바뀌는 문제
구글 시트가 "00001" 같은 값을 자동으로 숫자 1로 인식해버려서, 중복 확인할 때 매칭이 안 되는 문제가 있었다. 시트 서식을 일반 텍스트로 바꾸고, 코드에서도 앞자리 0을 제거하고 비교하도록 정규화 함수를 만들어서 해결했다.

### 중복 확인 로직에서 빈 값끼리 서로 매칭되던 버그
분석 결과 시트를 조회했을 때 나온 빈 아이템(Always Output Data로 생긴)의 이메일 값이 빈 문자열이고, 새로 들어온 문의 이메일도 우연히 비어있으면 둘 다 빈 문자열이라 "같다"고 판단되는 버그가 있었다. 이메일이 빈 값인 행은 비교 대상에서 미리 제외하도록 고쳐서 해결했다.

## 6. 느낀 점

노드 하나 연결하는 건 금방 하는데, 실제로 돌려보면 생각 못 했던 데이터 형태나 엣지 케이스에서 계속 걸렸다. 특히 시트에서 값이 숫자로 자동 변환되는 것, AI 응답이 중첩된 구조로 나오는 것처럼 눈에 잘 안 보이는 부분에서 시간을 많이 썼다. 그래도 하나씩 원인을 찾아서 고쳐나가니까 결국 다 돌아가게 만들 수 있었다.
