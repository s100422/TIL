# 옥상 위 고군분투! — 와이어 액션 게임

원버튼(마우스 왼쪽 클릭) 조작의 와이어 액션 스테이지 클리어 게임. 기와지붕 사이 낭떠러지를 와이어(뚫어뻥)로 스윙하며 건너 목표 지점(G)까지 도달한다.

## 기술 스택 / 구조 원칙

- 순수 HTML/CSS/JS, 프레임워크 없음. Canvas 2D API로 렌더링.
- `index.html` 진입, ES 모듈(`type="module"`)로 JS 파일 분리.
- 배경 이미지 한 장(`images/배경.png`)만 예외적으로 이미지 리소스를 쓰고, 그 외 모든 요소
  (캐릭터/지붕/전봇대/동전/UI)는 Canvas 2D 도형으로 그린다.
- 파일 구조:
  ```
  index.html
  css/
    style.css
  images/
    배경.png    // 밤하늘 배경(달/남산타워/스카이라인 포함) — 유일한 이미지 리소스
  js/
    autoplay.js   // 개발용 자동 플레이 하네스 (배포 제외). 동전 배치용 궤적을 뽑는다
    devtools.js   // 개발용 튜닝 패널 (배포 제외)
    main.js       // 진입점, 게임 루프(requestAnimationFrame), 전역 상태 조립
    config.js     // 중력/점프/속도 등 모든 손맛 튜닝 파라미터를 한 곳에 모음
    canvas.js     // 캔버스 셋업/리사이즈
    input.js      // 마우스 down/up/move, 커서 각도 계산
    player.js     // 플레이어 상태(위치/속도/state), 지상 점프 물리
    wire.js       // 와이어 발사(레이캐스트), 진자 운동, 릴리즈 시 관성 계산
    anchor.js     // 탑(앵커) 정의 및 히트 판정
    stage.js      // 스테이지 데이터(지형/탑/동전/G지점), 로드 및 재시작
    coin.js       // 동전 배치/획득, 퍼펙트 보너스 판정
    camera.js     // 오토런 스크롤, 스테이지별 속도 증가
    collision.js  // 지형/낭떠러지/장애물 충돌 판정
    renderer.js   // 캐릭터/와이어/지형/동전/UI 드로잉
    ui.js         // 점수/스테이지 표시, 타이틀 화면("게임 시작" 버튼), 실패 시 재시도 확인 팝업
  ```
- 모듈 책임을 섞지 않는다 (물리 계산은 `wire.js`/`player.js`에만, 그리기는 `renderer.js`에만).

## 조작 방식 (원버튼)

- **지상 상태**: 클릭 → 고정 구조 점프 (항상 동일한 높이/거리의 포물선. 타이밍만 신경 쓰면 됨).
- **공중 상태**: 클릭 → 등 뒤 와이어를 **마우스 커서 각도** 방향으로 발사 (수동 조준).
  - 와이어가 탑(앵커) 판정 영역에 명중하면 부착 성공.
- **와이어 부착 중**: 탑을 중심축으로 원운동(진자, `Math.cos`/`Math.sin` 기반)하며 스윙.
- **마우스를 뗀 순간**: 와이어 해제. 그 시점의 원운동 접선 방향 속도를 관성으로 변환해 사출 → 이후 중력 + 속도로 포물선 비행.
- **연속 와이어**: 공중 비행 중 사거리 내 다음 탑이 있으면, 다시 클릭+조준하여 연속으로 스윙 체인 가능 (탑 2~3개 연속 낭떠러지 구간).

## 상태 머신

`GROUND` ↔ `AIR_FREE`(발사 후 관성 비행/자유낙하) ↔ `AIR_WIRED`(와이어에 매달려 원운동)

- `GROUND`: 클릭 시 고정 점프 벡터 부여 → `AIR_FREE` 전환.
- `AIR_FREE`: 중력 가속 적용. 클릭 시 커서 각도로 레이캐스트 판정 → 탑 명중하면 `AIR_WIRED` 전환(현재 위치·탑 중심으로 초기 각도 theta 계산). 지붕에 착지하면 `GROUND` 복귀.
- `AIR_WIRED`: theta를 각속도로 갱신하며 원운동. 마우스 릴리즈 시 접선 속도(= 각속도 × 반지름, 방향은 원의 접선) 계산해 `AIR_FREE`로 복귀.
- 낭떠러지 낙하 또는 장애물 충돌 → 그 자리에서 멈추고 **"재시도?" 확인 팝업** 표시 (목숨 시스템 없음).
  - "재시도" 선택 → **코스 맨 처음부터** 재시작 (중간 체크포인트 없음).
  - "재시도 안 함" 선택 → 타이틀 화면("게임 시작" 버튼이 있는 첫 화면)으로 복귀.

## 스테이지 구성

무한 러너가 아니고, 스테이지별로 팝업이 끊기는 구조도 아니다. **하나로 쭉 이어진 코스**를
처음부터 끝까지 달리며, 진짜 마지막 목표 지점(G)에 도달했을 때만 "전체 클리어!" 화면이 뜬다.

- 캐릭터는 **항상 자동으로 전진**(오토런). 플레이어 입력은 점프/와이어 타이밍만 결정한다.
- 코스는 **와이어 챕터**(탑을 연속으로 걸어 낭떠러지를 건너는 구간)와 **휴식 구간**(탑 없이
  평평한 지붕만 있고 그냥 달리며 동전을 먹는 구간)이 번갈아 나온다. 와이어 챕터가 너무 촘촘하면
  피로해지므로, 챕터 사이에 반드시 숨 돌릴 공간을 둔다.
- 진행 속도(오토런 배율)는 스테이지 단위 계단식이 아니라 **코스 진행 거리에 비례해 매끄럽게**
  1.0배(시작)에서 1.6배(끝)까지 오른다 (`stage.speedScaleAt(x)`).
- 추락 시 재시작은 항상 **코스 맨 처음**부터 — 중간 체크포인트는 없다.
- 레벨 요소: 일반 지붕(안전 지대/휴식 구간) — 낭떠러지(갭, 와이어 챕터) — 공중에 뜬 탑(와이어 앵커).
- 동전은 **별사탕**(분홍 = 기본, 금색 = 보너스)이다. 한 구간의 별사탕을 모두 획득하면
  **퍼펙트 보너스** 점수 지급 (전 12구간).
- **별사탕 배치는 손으로 찍지 않고, 자동 플레이로 기록한 실제 이동 궤적 위에 얹는다**
  (`stage.js`의 `COINS` 표, 궤적을 호 길이 105px마다 샘플링). 눈으로 보기 좋은 높이에
  뿌리면 실제로 지나가는 곳이 아니다 — 진자 운동은 앵커(y=175)에서 줄 길이만큼 아래를
  지나므로 호의 최저점이 옥상선(y=440) 근처이고, y 300대는 캐릭터가 닿을 수 없는 높이다.
  지상 구간은 궤적보다 18px, 공중 구간은 14px 위로 올린다(획득 판정 반경 26px 안).
- **스윙 높이는 갭 폭이 결정한다.** 진자는 '떨어지면서' 속도를 얻으므로, 한 번의 호로
  건너야 하는 거리가 멀면 줄이 길어지고 호가 옥상선 밑까지 처진다("사람이 하기엔 너무 낮다").
  앵커만 촘촘하게 늘리는 것으로는 안 된다 — 앵커가 머리 위면 이미 호의 최저점이라
  올라갈 높이가 11px뿐이고 속도도 못 얻어서 전부 추락했다(실측).
  그래서 **갭을 250~320px로 좁히고 전봇대를 짝으로(간격 105~130px) 배치**했다.
  결과: 공중 별사탕 y가 중앙 440 → 373, 가장 낮은 것 512 → 402로 올라와 전부 옥상선 위.
- 별사탕을 궤적보다 더 올리는 것으로는 해결되지 않는다 — 판정 반경이 26px이라 리프트를
  14→26px로 키워도 높이는 12px만 얻고 획득률이 20%p 떨어졌다(실측).
- 목표 지점(G) 뒤로는 별사탕을 두지 않는다 — G에 닿는 순간 클리어 처리되므로 구조적으로
  먹을 수 없다.
- `stage.js`는 6개의 '챕터'(예전 스테이지 1~6에 해당하는 난이도)를 코드에서 이어 붙여
  하나의 코스로 만든다 — 챕터별 갭 폭/탑 간격은 자동 플레이(`js/autoplay.js`)로 완주 가능함을
  검증한 값이다. 갭은 250~320px이고 갭마다 전봇대를 2개씩(간격 105~130px) 둔다.
  값을 바꾸면 자동 플레이로 완주 가능성과 스윙 높이를 반드시 다시 재야 한다.

## 개발 순서 (MVP 로드맵)

1. **스윙 물리 프로토타입**: 배경/장애물 없이 앵커 하나 + 캐릭터로 발사→부착→진자→릴리즈→관성비행 손맛만 완성. (`player.js`, `wire.js`, `anchor.js`, `input.js`, `renderer.js` 뼈대)
2. **지상 점프 + 상태 전환**: `GROUND`/`AIR_FREE`/`AIR_WIRED` 전체 상태 머신 연결.
3. **스테이지 데이터 & 재시작**: 지형/낭떠러지/탑 배치, G지점 도달 판정, 낙사 시 즉시 재시작.
4. **동전 & 퍼펙트 보너스, 스테이지별 속도 증가**.
5. **비주얼 다듬기 & 사운드** (스타일 미정 — 우선 도형 placeholder로 물리 검증 후 결정).

## 비주얼 컨셉 (CP23에서 확정, 배경은 이후 이미지로 교체)

"옥상 위 고군분투" — 캐릭터는 평범한 사람, 발 딛는 지붕은 도시 건물 옥상(살구색 벽면 +
파란 창문 + 크림색 옥상 테두리, 눈에 잘 띄는 플랫 컬러), 와이어 앵커는 전봇대(가로대+애자) —
동전은 별사탕(둥근 몸통 + 짧은 돌기 7개, 파스텔 분홍/금색) — 이 부분은 전부 Canvas 2D 도형으로 그린다.

배경(서울 밤 스카이라인 — 달/남산타워/도시 실루엣)은 도형으로 직접 그리는 대신
`images/배경.png` 한 장을 캔버스 전체에 고정으로 그린다(카메라 위치와 무관, 스크롤/패럴랙스
없음). 이미지 자체에 달과 남산타워가 이미 들어 있어 "항상 같은 자리에 보이는 랜드마크"
요구사항을 그대로 만족한다.

단, 이미지 아래쪽의 **지하철은 정지 화면으로 두지 않는다.** 하늘 부분(원본 0~568행)만
고정 배경으로 깔고, 지하철 띠(569~745행)는 따로 떼어내 심연 안에서 왼쪽으로 흘려보낸다 —
낭떠러지 틈으로 노란 창문이 지나가는 것이 보인다. 카메라가 아니라 누적 시간으로 움직이므로
타이틀 화면이나 추락 팝업에서도 계속 달린다.

**지하철 차량 지붕은 옥상 높이(`stage.abyssTop` = 440)에 정확히 맞춘다** — 이미지의 원래
배율로 두면 차량이 옥상선보다 32px 위로 솟아 건물보다 높이 뜬 것처럼 보인다. 지붕을 옥상선에
맞추면 남는 세로 공간이 100px뿐이라 가로세로 같은 배율로 줄여 선로 끝이 화면 바닥에 닿게 한다.
하늘도 같은 이유로 옥상선까지 늘려 그린다(원래 지하철이 있던 40px을 메우려면 그래야 하고,
이미지에서 지하철 바로 위 띠는 세로로 균일하지 않아 늘려 메우면 얼룩이 생긴다).

그리기는 전부 `renderer.js`에 있다(`drawBackground()`가 하늘, `drawAbyss()`가 심연+지하철,
나머지 함수들이 도형 요소를 담당).

## 미정 사항 (추후 결정 필요)

- 스코어 세부 공식 (동전 점수량, 퍼펙트 보너스 수치, 스테이지 클리어 랭크 등).
- 사운드/BGM 포함 여부.
