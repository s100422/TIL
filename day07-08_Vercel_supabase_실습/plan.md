## 핵심 기능

---

- 배달 음식 카테고리 사용자화 _예시) 야식땡길 때, 오븐 치킨, BBQ지점들 …_
- 식당 등록
    - 사용자 등록 `user_id`
    - 사용자 닉네임 `nickname`
    - 카테고리 설정 (선택) `categories`
    - 식당 이름 (필수) `restaurant_name`
    - 식당 주소 (선택) `restaurant_address`
    - 배달 시켜 먹은 적 있나? (True/False) `usedDelivery`
        - 유: 평점 `score` 및 리뷰 `review` 남기기 (선택) _예시) 4.5(`score` ,평점 0.1 단위로) / 치킨 튀김옷 두께 적당, 기름 냄새 안남. 양념소스는 많이 안 줌 하나 더 시켜야함. (`review`)_
        - 무: 특이사항 `memo`에 넣어 놓은 이유 쓰기 (선택) _예시) bbq 새로운 지점. 맛볼 예정_
    - 특이사항 `memo`적기 (선택)
- 등록된 식당 수정, 삭제
- 카테고리 별 정렬: 최신 등록 순, 오래전 등록 순, 평점 높은 순, 평점 낮은 순 (드롭박스)
- 전체 식당 별 정렬: 최신 등록 순, 오래전 등록 순, 평점 높은 순, 평점 낮은 순 (드롭박스)

## 로그인 & 데이터 영속성 (2026-08-04 추가 요구사항)

---

- 문제: 현재 `user_id`가 브라우저 `localStorage`에 저장된 랜덤 UUID라서, 브라우저 캐시 삭제/다른 브라우저·기기 접속 시 등록한 데이터에 다시 접근할 수 없음
- 해결: Supabase Auth의 이메일/비밀번호 로그인 도입 (카카오 등 소셜 로그인은 추후 필요 시 추가 — 지금은 별도 개발자 앱 등록 없이 바로 붙일 수 있는 이메일/비밀번호로 진행하기로 결정)
- 로그인 필수 — 온보딩(닉네임/카테고리 설정) 전에 로그인부터 진행
- 로그인 성공 시, 이 브라우저에 남아있던 기존 localStorage user_id의 categories/restaurants가 있으면 새 로그인 계정 id로 자동 이전(마이그레이션)
- `categories`/`restaurants`의 `user_id`를 로그인한 계정의 auth user id 기준으로 저장, RLS 정책도 `auth.uid()` 기준으로 강화

## 테이블 설계

---

| 이름                   | 타입         | 크기      | 설명                        |
| -------------------- | ---------- | ------- | ------------------------- |
| `user_id`            | Int        | -       | 유저 id (Primary key, 자동생성) |
| `nickname`           | Text       | 10자 이내  | 사용자 닉네임                   |
| `categories`         | Text       | 10자 이내  | 사용자가 만든 카테고리              |
| `restaurant_name`    | Text       | 10자 이내  | 식당 이름                     |
| `restaurant_address` | Text       | 20자 이내  | 식당 주소                     |
| `usedDelivery`       | True/False | -       | 배달시킨 경험이 있는지 확인           |
| `score`              | Float      | -       | 평점                        |
| `review`             | Text       | 500자 이내 | 리뷰                        |
| `memo`               | Text       | 500자 이내 | 특이사항                      |

## 흐름

- 사용자 닉네임 만들기 `user_email` → 사용자 카테고리 1개 이상 만들기 `categories` → 식당 등록 `restaurant_name` → 카테고리 넣고 `categories` , 식당 이름 `restaurant_name`, 식당 주소 `restaurant_address`, 배달시킨 경험 확인 `usedDelivery`, 평점 `score`, 리뷰 `review`, 특이사항 `memo` 등록하기

## 요약 🌟

---

배달 음식을 시킬 때 같은 치킨이라도 구운 치킨, 바비큐 치킨, 크리스피 후라이드, 양념 후라이드 등등이 있고 치킨 집 대부분은 다양한 종류의 치킨을 판다.

하지만, 나의 치킨집 경험 데이터베이스를 쌓아 놓고 그걸 한눈에 볼 수 있다면 양념 치킨은 어디 브랜드 어느 지점이 맛있고(같은 브랜드라도 맛이 다 다르다), 오븐 치킨은 어느 지점이 맛있는지 한 눈에 확인하여 맛있는 치킨을 먹을 수 있다.

배달음식이 너무 많지만 맛있는 곳은 드물고, 평점을 남길 때도 대부분 리뷰이벤트 때문에 싫은 소리를 쓸 수 없다. 이 서비스는 나만의 공간에서 아주 신랄하게 맛을 비판하는 것도 가능하다.
