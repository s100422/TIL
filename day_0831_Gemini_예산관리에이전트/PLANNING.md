# 프로젝트 기획서

> 작성일: 2026-08-31 / 작성자: 문수진 / 버전: v1.0

## 1. 개요
- **프로젝트명**: 개인 예산 관리 AI Agent
- **한 줄 요약**: Gemini Function Calling을 이용해서, 사람 말(자연어)로 지출/예산을 등록하고 관리할 수 있는 챗봇을 만든다.
- **목적/배경**: 파이썬으로 배운 것을 활용해서 AI가 함수를 직접 호출하는 구조를 직접 만들어보고, 그 원리를 이해하기 위함이다.

## 2. 목표
- **하고 싶은 것 (Must)** — 다 완료함
  - 지출 등록 / 수정 / 삭제 / 검색
  - 예산 등록 / 수정 / 삭제 / 검색
  - 이번 달 예산이 얼마 남았는지 확인
  - 없는 데이터를 조회했을 때 에러 처리
- **되면 좋은 것 (Nice to have)** — 다 완료함
  - 거래 내역을 파일(json)로 저장해서, 챗봇을 껐다 켜도 데이터가 안 사라지게 함
  - 월별 거래 내역을 Markdown 파일로 저장해주는 기능
- **이번엔 안 할 것 (Out of scope)**
  - 통계나 그래프로 보여주는 기능
  - 여러 명이 같이 쓰는 기능 (로그인, 계정 나누기 등)

## 4. 사용자 시나리오
사용자: 오늘 점심으로 12,000원 썼어.
Agent: 지출 내역을 식비 카테고리로 등록한다.

사용자: 2026년 8월 27일 카페에서 쓴 금액을 4,500원으로 수정해줘.
Agent: 조건에 맞는 거래를 찾아서 수정한다. 같은 날 같은 카페 지출이 두 건 있으면, 둘 다 보여주고 어떤 걸 말하는 건지 다시 물어본다.

사용자: 이번 달 예산이 얼마나 남았어?
Agent: 이번 달 예산과 지출을 다 더해서 남은 금액을 알려준다.

사용자: 2026년 8월 지출 내역을 파일로 저장해줘.
Agent: 그 달의 예산/지출을 정리해서 Markdown 파일로 저장한다.

## 5. 기능 명세 (Function 목록)
| 함수명 | 설명 | 주요 파라미터 |
|---|---|---|
| `register_expenditure` | 지출 등록 | `amount`, `date`, `tag` |
| `alter_expenditure` | 지출 수정 (id로 실행, 없으면 후보만 반환) | `id`, `date`, `tag`, `new_amount` |
| `delete_expenditure` | 지출 삭제 (id로 실행, 없으면 후보만 반환) | `id`, `date`, `tag` |
| `search_expenditure` | 지출 검색 (기간/태그) | `s_date`, `e_date`, `tag` |
| `register_budget` | 예산 등록 | `amount`, `date`, `tag` |
| `alter_budget` | 예산 수정 (지출과 동일한 방식) | `id`, `date`, `tag`, `new_amount` |
| `delete_budget` | 예산 삭제 (지출과 동일한 방식) | `id`, `date`, `tag` |
| `search_budget` | 예산 검색 | `s_date`, `e_date`, `tag` |
| `get_remaining_budget` | 이번 달(또는 지정한 달) 예산 - 지출 계산 | `month` |
| `save_report` | 그 달의 예산/지출을 Markdown 파일로 저장 | `month` |

## 6. 아키텍처 / 데이터 흐름
```
사용자 입력 → Gemini API (어떤 함수를 쓸지 판단)
           → 파이썬 함수 실행 (지출/예산 데이터 읽고 쓰기)
           → 실행 결과 파일로 저장 (data.json)
           → 결과를 Gemini에 다시 전달
           → 사람이 이해하기 쉬운 문장으로 최종 응답
```
- `Ledger` (지출/예산 데이터를 담고 있는 부분): 파이썬 메모리 + `data.json` 파일에 저장
- 요청하면 `reports/2026-08.md` 같은 Markdown 파일도 따로 생성됨

## 7. 기술 스택
- 언어: Python 3
- 주요 라이브러리: `google-genai` (Gemini API 호출), `python-dotenv` (API 키 관리)
- 표준 라이브러리만으로 처리한 부분: `json`(데이터 저장), `os`(경로/파일), `datetime`(날짜 계산)
- 실행 환경: 처음엔 파일 여러 개(`ledger.py`, `report.py`, `tools.py`, `agent.py`)로 나눠서 만들었다가, 마지막에 `mini_project.ipynb` 노트북 하나로 합침

## 8. 진행하면서 크게 바뀐 부분

### (1) 거래마다 고유 번호(id) 부여
**문제**: 처음엔 거래를 "날짜 + 태그"로만 구분했다. 근데 같은 날 같은 카페를 두 번 가서 지출을 두 번 등록하면(예: 8/18 카페 13,000원, 8/18 카페 5,000원), "8/18 카페 지출 지워줘"라고 했을 때 둘 중 뭘 지워야 할지 구분이 안 돼서 두 개를 합친 금액(18,000원)이 통째로 지워지는 문제가 있었다.

**해결**: 지출/예산을 등록할 때마다 절대 겹치지 않는 번호(id)를 하나씩 붙이기로 했다. 이제 수정/삭제는 이 번호로만 실제로 실행되고, 번호 없이 날짜/태그만 주면 "이 중에 어떤 거예요?" 하고 후보 목록(번호 포함)만 보여준다. 사용자가 번호를 골라주면 그걸로 정확하게 하나만 처리한다.

### (2) 예산이랑 지출 코드가 완전히 똑같음 → 하나로 합침
지출을 관리하는 코드랑 예산을 관리하는 코드를 각각 따로 만들었는데, 나중에 보니 이름이랑 에러 메시지에 나오는 단어("지출" vs "예산") 빼고는 100% 똑같은 코드였다. 그래서 두 개를 `Ledger`(원장)라는 클래스 하나로 합치고, "이게 예산인지 지출인지"는 이름표(label) 하나만 다르게 줘서 구분하게 바꿨다. 덕분에 코드 양이 절반으로 줄었고, 나중에 로직을 고칠 때 한 곳만 고치면 되게 됐다.

### (3) 데이터 저장 기능 추가 - 번호(id)도 같이 저장
처음엔 챗봇을 끄면 등록해둔 데이터가 다 사라졌다. 그래서 데이터를 `data.json` 파일에 저장했다가 다시 시작할 때 불러오는 기능을 추가했다(과제의 추가 구현 부분이지만 필수인 것 같다!). 그런데 (1)번에서 번호(id)를 쓰게 되면서, 이 "다음 번호가 몇 번인지"도 같이 저장해야 한다. 그렇지 않으면 다시 시작했을 때 번호가 0부터 다시 매겨지면서 기존 번호랑 겹친다.

### (4) 파일 여러 개 → 노트북 하나로 합치면서 생긴 문제들
`.py` 파일 여러 개로 나눠서 만든 코드를 노트북(`.ipynb`) 하나에 합쳐 넣으면서, 파일 환경에서만 되던 코드 두 개가 걸렸다:
- `__file__`(지금 파일 경로): 노트북 안에서는 이 값이 없거나 이상하게 나와서, 대신 `os.getcwd()`(현재 폴더 경로)로 바꿨다.
- `sys.stdout.reconfigure(...)`(콘솔 출력 인코딩 문제 방지용 코드): 노트북은 출력이 콘솔이 아니라 화면으로 바로 나가서 애초에 이 코드가 필요 없어서 지웠다.

또한 노트북에 코드를 넣을 때는 **순서가 중요하다** — `ledger` → `report` → `tools` → `agent` 순서로 셀을 배치해야, 뒤에 나오는 코드가 앞에서 만든 것들을 문제없이 사용할 수 있다.
